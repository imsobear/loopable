A lot of team work does not

The knowledge is already in the tools.

Code review, digging a case, reading monitors. It should not wait on whoever has Codex open. Those jobs stall the same way: ping, “I’ll look later,” laptop sleeps, nothing ran.

Shared-knowledge work

Jobs that do not need an owner with a laptop.

  • 01

    Code review

    A teammate is assigned. The loop reads the diff and leaves a review. Nobody copies the PR into a chat.

  • 02

    Dig a case

    An on-call thread, a spike, a failing checkout. The agent reads the logs and writes back where the team already is.

  • 03

    Read the monitors

    A morning sweep, a latency alert, stale issues with no comment. Scheduled or triggered. Same runner.

How a job runs

One path. Slack, GitHub, and the clock only change the signal.

  1. Signal Something the team already does: an @mention, an assignment, nine o’clock.
  2. Loop A job you already wrote. It names the agent, not a person.
  3. Runner Codex or Claude on a shared machine. The answer is written back. The inbox is the record.

Loopable is not a coding agent. Codex and Claude are. Loopable watches, dispatches, and writes back so nobody has to open the agent.

How you run it

One computer that stays on.

A Mac in the office is enough. App, Dispatcher, and a Runner live there. Extra runners or a company VM only if that box is not enough. 

npm install -g loopable-cli
loopable start
loopable runner --url http://<LAN-IP>:4321 --token <from Runners>
